# p10 step 5 — Editor views and delegation-aware observation

## What was done

**Editor** (agdevworld):

- **Delegate inspector**, in both modes:
  - *Delegate to project* (this project or any other registered one);
  - *Delegate to workflow* (that project's workflows; this workflow is
    disabled, and a target without intake is marked);
  - *Who accepts the child's result* (`person` / `parent`).
- **Validation**: workflow responses and validation now know the other
  registered projects (`server/peers.ts`, supplied by the service and the
  CLI). Unknown cross-project targets, missing intake and cross-project
  recursion are found while editing. The canvas names a cross-project target
  as `project/workflow`, also in the run view, where it is no longer marked
  "missing".
- **Run view**:
  - The delegate card says where the child stands ("Waiting · child
    waiting", "news to take up", the disposition).
  - The selected delegate node and Detail's new *Delegations* section show
    the child, with links (child run view, conversation, progress, detailed
    IO), the next move, what the child asked and how it was answered, the
    result manifest and the disposition.
  - The focus card says "Waiting for kid/make — its child make/run-001 is
    waiting for an answer. Open the child run", or that the agent has news
    to take up. Before, it fell through to "Waiting for the executor —
    nothing is running".
  - The executor chip reads "idle, waiting for a delegated run".
  - A child's *Related runs* links to the run that delegated it.
  - Child facts are read in host refreshes as well, so the child's progress
    shows without a change of the parent's record.
- **Node catalog**: `delegate` is now a template type, with an optional
  `target {project, workflow, accepts}` copied into the node. It is a
  description of a delegation task, not a plugin framework. `wfe nodes
  create … --type delegate --target-project … --target-workflow …
  --accepts …`.

**Observation** (`server/observe.ts`, `docs/observation.md`):

- Each run with delegations carries `delegations[]`:
  - the child read from its own record (situation, execution, waits, hold,
    failures);
  - the parent's untaken facts;
  - the child facts not yet relayed;
  - before a child exists, the request delivery's state from the notifier's
    journal (read-only).
- A delegate node's wait names `delegation:<child uid>` or
  `delegation-unbound:<uid>`. A relayed fact with no queued job is
  `executor`, i.e. an unowned continuation.

**Observer** (`agobserver/src/agobserver/wfclassify.py`, `docs/workflow.md`):

- New condition `awaiting-delegation` (quiet).
- `relay-stalled`: a waking child fact not on the parent for 300 s;
  `unbound-dispatch`: no child for 900 s, or a failed or uncertain delivery.
  Both are family `delegation` and go to the owners. Recovery is not asked:
  the relay and delivery are WFE's.
- The child's own interruption or failure stays the child's incident only.
  The parent is never a second incident.
- Human holds are respected as before.

**Observer fixtures**: seven new `tests/fixtures/workflow/delegation-*.json`,
generated by the real `Observer.observe()` over real delegation scenarios
(`pj-agdev/.local/workflow-editor-p10/step5/fixtures.ts`; host names
replaced). All classify as specified:

- a healthy wait is `awaiting-delegation`, with the child `queued`;
- a relayed question leaves the parent `queued` and the child
  `awaiting-person`;
- a lost continuation is `unowned` (continuation, recoverable);
- a parent held by Pat is `respected-hold`;
- an unrelayed question after 600 s is `uncertain` (delegation,
  relay-stalled), not recoverable;
- a dispatch whose post was never acknowledged, after 1200 s, is
  `uncertain` (delegation, unbound);
- an interrupted child is `interrupted` (attempt, recoverable), while its
  parent stays `awaiting-delegation`: no duplicate.

**Child progress without parent attempts**: in the check and the fixtures,
the child's facts (its question, its waits, its interruption) are visible
from the parent's view and observation while the parent has no open
attempt and no job. Only a waking fact queues one.
