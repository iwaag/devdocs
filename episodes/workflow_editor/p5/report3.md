### Editor (definition view)

- **Policy at creation.** The policy can be chosen in the project view's "New workflow" form, the HTTP API (`policy`), and `wfe workflow new --policy`. It defaults to `default`.
- **Policy afterwards.** It is edited under "Workflow settings" in the inspector (nothing selected). An undeclared or unsupported value is shown as such.
- **Preview.** `compile(draft)` — the same compiler run creation uses — supplies the canvas with the generated steps:
  - the **plan talk** is a normal-sized talk card before the entry cards (dashed border, its own `.step-card` class, so it is never counted or edited as an authored card);
  - every **report** is a 30 px, desaturated, circular icon overlapping its card's lower-right corner by a fixed 18 px. It has no position of its own: it is placed from its card's box and follows the card while it is dragged;
  - the **final report** is a compact endpoint after the terminal cards;
  - dashed `.step-edge` lines run from the plan card to the entry cards and from the terminal reports to the final report. The primary authored edges stay as they were.
- **Status line.** It states what a run adds ("a run adds the plan talk, 4 reports and the final report"), or why the preview is unavailable (the compiler's refusal), or that the policy is manual or undeclared.
- **Selecting a step.** The inspector shows it read-only: a "generated by the default policy" note, its document, what it waits for and what follows it ("successors of build wait for this report"), and the frozen instructions in a collapsible block.
- **Fit, zoom, reveal and panning** include the plan card, the icons and the endpoint.
- **Approvals.** Changing the policy re-renders the preview and makes definition approval stale. Intent approval stays as it was. A layout move changes neither.
- **Draft protection.** Run events do not touch an unsaved draft. This is unchanged code, now checked with a policy edit pending.

### Run view

- **Frozen graph.** The canvas draws `definition.effective` from the run, never a recompilation.
- **States.**
  - The authored card shows its work state and the report icon shows the report state.
  - A running report pulses, is labelled "Writing report", and the summary's Active line reads "Writing report on build".
  - States carry a glyph (○ ◇ ⊘ ✎ ⏸ ✓ ✕ –) and an `aria-label` as well as color. The legend uses the same glyphs.
  - The pulse animation respects `prefers-reduced-motion`.
- **Step detail.**
  - Document state: *not written yet* / *being written — not yet recorded* / *written, not recorded as complete* / *checked when recorded* (bytes, sha256), with **Open**, which reads the file through the existing run-file route.
  - The plan step names the agreeing question.
  - Report dependencies are explained, and an authored node's detail links to its report.
- **Counts.** Summary facts count work and documentation steps apart ("Work: 2 completed · 2 pending", "Documentation steps: 1 running · 2 completed · 3 pending"). Runs from before p5 show "none (created before p5)"; manual runs show "manual — no generated plan or reports".
- **Manual policy runs** show no generated steps.

The p4 code shows the same crash (baseline below), so this was a p4 bug.

## Limitations

- **Plan card placement.** The plan card sits one column left of the leftmost entry card, at the entry cards' mean height. In a hand-arranged graph whose entry cards are far apart vertically, it may sit between them. It is not movable by design (no position of its own).
- **Final endpoint placement.** The final endpoint is placed one column right of the rightmost card.
- **Stale p4 checks.** step2, step3 and e2e were not repaired. The failing checks are unrelated to documentation steps and are recorded above.
