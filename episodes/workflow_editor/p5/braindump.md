# zulipとplan/report

braindump.md->plan.md->report.mdがdevdocsの各runのフォルダに残り、zulipには人間や他のエージェントから見てざっくり状況を把握できる程度のごくごく簡潔な進捗が残るようにしたい。そうすれば、他のエージェントや人間からすると、zulipで概要チェックして次のアクションを決め、必要に応じてdevdocsをチェック、さらに必要ならソースコードや生成されたアセットなどの実成果物チェックという３段階の流れができる。理想は、大部分はzulipで完結、問題や怪しむべき報告が起きた時にdevdocs、さらに根深い問題ならソースコードチェック、つまりざっくり7:2:1ぐらいのチェック頻度でトラブルシューティングや連携が安定して進むことだ。

今のagautolab管理下プロジェクトは、workflow_editorの追加でややレガシーになっているはずだ。後方互換不要の原則で、いずれ互換性を維持する必要も、引き継ぐ必要もない。ただ、運用方法には引き継げる部分もありそうだ。プロジェクトを作成したらzulipにプロジェクトフォルダを作成し、ワークフローごとにチャンネルを作成、runごとにtopicを作成という構成がきれいな気がする。

また、plan.mdやreport.mdを作るタイミングはどうしようか。大きく二つの考え方に分けられると思う。

1. planもreportも暗黙的に生成する。たとえばplanは最初のノードの前、report-(node id).mdをノードごと、最初のノードの後という感じ。楽だがコントロールしずらい。
2. 明示的に作成。planもreportもplanノードとreportノードにして明示的に配置。面倒だしノード数が一気に膨張するが柔軟。

この両方の良いとこどりができないかと考えている。
ワークフロー編集の初期設定で、planとreportのポリシーを決める。種類はひとまずdefaultとmanualのみ。
defaultは最初にplan.md作成のためのtalkを挿入し、各ノードの最後に必ずreport-(node id).mdの作成のための小さなノードを入れ、最後に最終レポートreport.mdの作成ノードを挿入する。reportノードの表示は他のノードよりずっと小さく、アイコン一個の円形ノードとし、彩度をすこし下げて目立たなくした上で、下のノードの右下の固定位置に表示する。p5ではこっちを前提に実装してみる。report.mdの作成は実際にはノード実施時のプロンプトに指示を追加するだけで、特別な決定論的処理を追加する必要はないと思う。が、UI上の表示としては、実行フェーズが完了したら、reportアイコンの方がハイライトされて報告を作成中ということがわかるようにしてほしい。
manualは完全にユーザーの判断に任せ、明示的に指示されるまでプランもレポートも作成しない。こちらはp5の時点で特別にplanノードやreportノードを手動で追加できるようにしなくていいし、ほぼ未実装の状態でいい。
