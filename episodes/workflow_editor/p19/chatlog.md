## 確認できたこと(aghangout main@3c94b6c と WFE docs/conversations.md・challenges.md の読み取りによる)
- 現状のメッセージ送信 `POST api/conversations/<id>/messages` が運べるのは `text, token, to, runs, re, challenges` だけで、ファイルを運ぶ口はありません。
- 既存の「添付」は challenge 添付だけです。これは共有 Git リポジトリ(`challenges/ch-NNNN/`)の内容を、メッセージ送信時の commit に固定して(pin して)付ける仕組みです。会話に関わる全プロジェクトが `wfe challenge` で読めます。1ファイル 32MB、1回の書き込み 64MB の上限があり、画像などの base64 アップロードにも対応しています。
- 画面側のコードは `app/src/room.ts` にあり、composer への paste / drop は今のところありません。

## 保存先の案
**案A(推奨): WFE にメッセージ添付ストアを新設**
- 保存: WFE が管理する共有 Git リポジトリを使います。challenge と同様、全プロジェクトから読めます。パスは `conversations/<会話id>/m<メッセージ番号>/<sha256先頭>-<元のファイル名>` とします。
- 対応づけ: メッセージ記録に `attachments: [{kind:'file', name, mime, size, sha256, path, commit}]` を持たせます。メッセージ番号がパスに入るうえ、sha256 と commit も記録するので、「どのメッセージの添付か」は取り違えようがありません。
- 経路: 送信は `POST …/messages` に `files:[{name, base64}]` を足します。まず1回のリクエストで WFE がメッセージとファイルを同時に確定させます。メッセージが先に確定して添付だけ失敗する、という中途半端な状態を作りません。
- 参照: 返信を書くエージェントには、run の入力に添付の実体パスと説明を渡します。`wfe conversation show` にも添付を表示します。
- 上限は challenge と同じ水準(1ファイル 32MB)にします。

**案B(暫定・WFE無改造): challenge を流用**
- 送信時に aghangout が「1メッセージ=1 challenge」を作り、ファイルを載せ、`challenges:[id]` で添付します。pin によって対応づけは確実です。
- 欠点は、challenge は「後で解決すべき問題」の記録なので、添付のたびに問題一覧が汚れることです。「メッセージのファイル置き場」という意味づけも歪みます。つなぎとしては動きますが、本命にはしません。
